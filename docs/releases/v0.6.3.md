# pumr v0.6.3

A Linux release for graphics and window problems: pumr starts again on Wayland
with the NVIDIA driver, renders sharply on X11, and the window-toggle shortcut
no longer loses the window or ends the app.

## 🐛 Bug Fixes

- Fixed pumr not starting on Wayland with the proprietary NVIDIA driver. The process ended before a window appeared with `Error 71 (Protocol error) dispatching to Wayland display`; pumr now turns the driver's explicit sync off for itself, which keeps GPU rendering.
- Fixed a blurry interface, or a blank window, on X11. WebKitGTK's renderer that hands GPU buffers to the X server is the cause, so X11 sessions now use the renderer without them, as `WEBKIT_DISABLE_DMABUF_RENDERER=1` did by hand.
- Fixed pumr closing on X11 after the window-toggle shortcut was pressed a few times, with `[xcb] Unknown sequence number while processing queue`. libX11 before 1.8 (Ubuntu 22.04, Pop!_OS 22.04) is not thread-safe unless asked to be; pumr now asks at startup.
- Fixed the window-toggle shortcut hiding pumr for good on X11. A hidden window still counted as the active one when no other window took the focus, so the shortcut hid it again instead of bringing it back.

## ✨ Improvements

- pumr recovers on its own from Linux graphics setups that end it at startup: when a start does not survive its first 20 seconds, later starts use WebKitGTK's slower renderer without GPU buffers. Deleting `~/.cache/dev.pumr.app/webkit-startup` makes pumr try the fast one again.
- `__NV_DISABLE_EXPLICIT_SYNC` and `WEBKIT_DISABLE_DMABUF_RENDERER` are left alone when they are already set, so a value chosen by hand wins.

## 🔧 Maintenance

- The Linux rendering environment is chosen in one place (`rendering.rs`) before the webview exists, with Rust tests for the session detection and the startup marker.
- `x11-dl` is a direct Linux dependency for `XInitThreads`.
