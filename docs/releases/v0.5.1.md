# pumr v0.5.1

A focused command-permission release: prompts now explain how risky a command is
and let you grant access at the scope you actually mean, with a real command
denylist and a redesigned rules section. Plus a few quality-of-life fixes.

## 🚀 Features

- Added a severity chip (low / medium / high / danger) to command permission prompts, with a hover and keyboard-focus tooltip explaining the concrete impact. Compound commands use their worst segment.
- Added per-segment risk breakdowns to command prompts, highlighting which parts are already allowed and which still need approval.
- Added selectable rule scopes at command prompts: program (`ls *`), program + flags (`ls -la *`) or exact (`ls -la /test`), with a live rule preview. Compound commands offer scopes for every asking segment.
- Added "Allow in this chat": a command can be approved for the current session only, without being written to settings. It is cleared on restart or when the session is deleted.
- Added a command denylist. "Deny always" now persists the chosen scopes to a denylist, and a matching command is denied without a prompt.
- Redesigned the Commands and Websites sections in settings with separate allow and deny lists, counts, empty states, delete buttons, scope badges (program / program + flags / exact, domain / glob) and a shared add input.
- Added a "Fill the screen" option to window summoning so the restored window fills the active monitor instead of keeping its previous size.
- The `question` tool now marks a preferred option with a "(Recommendation)" label.

## ✨ Improvements

- Consume the head of a session's prompt queue as soon as the send actually starts, so a dispatched prompt leaves the queue immediately instead of lingering until the turn finishes.
- Surface cancellation observed by a tool so the turn stops instead of asking the model for another iteration, and let `glob` abort early when cancelled.
- Refresh settings after "allow always" / "deny always" so the rule lists update immediately without reopening settings.

## 🔧 Maintenance

- Publish the hand-written `docs/releases/vX.Y.Z.md` notes into the GitHub release body from the installer workflow.
- Added a GitHub release-notes generator config with feature, improvement, fix, maintenance and security categories.

## 🔒 Security

- Validate renderer-chosen command scopes against the options the backend proposed; any other value falls back to the backend's suggestion, so the renderer can never widen access.
- Ignore the renderer-supplied rule and folder for command prompts and persist only what the backend proposed.
- Keep deny rules strictly restrictive: they never bypass the built-in dangerous-command and path checks.
- Added tests covering scope options, denylist evaluation, session command rules and the "allow in this chat" lifecycle.

## ⚠️ Notes

- Requires Node 24 or newer to build from source.
