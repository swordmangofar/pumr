# pumr v0.5.2

A command-permission correctness release: rules now carry their matching kind
(exact vs glob), approvals are scoped to the session and resource they were
granted for, and automatic executable trust is verified against the real `PATH`.
Plus copy buttons across the chat.

## 🚀 Features

- Added copy buttons to assistant messages, tool command output and permission prompts.
- Added an exact/glob selector when adding a command rule in settings; rules are stored with their matching kind.

## ✨ Improvements

- Command rule badges in settings and prompts now show the actual matching kind (exact / glob) instead of guessing from the rule text.
- Permission approvals are scoped per session, operation, resource and command working directory. Identical commands in different chats or directories now prompt independently, and sensitive-file reads no longer share an approval with writes.
- Ordinary read-only tools keep automatic approval only when the executable can be resolved to a trusted location on `PATH`.

## 🐛 Bug Fixes

- Fixed a deadlock in `git check-ignore` when checking very large candidate sets by feeding stdin from a separate thread.
- Chat auto-scroll now follows content updates rather than scroll events, keeping streamed output pinned only when you are already at the bottom.

## 🔒 Security

- Command rules are typed exact/glob values: exact rules compare command text literally (wildcards such as `*`, `?`, `[`, `]`, `{`, `}` and `\` are literal), while glob rules keep intentional pattern behaviour. Rules with identical text can coexist and be selected or deleted independently.
- Renderer-submitted command rules are validated against the scopes the backend proposed; selections that do not match are ignored instead of widening access.
- Legacy string allow rules are discarded on load so they must be reapproved; legacy deny rules are preserved as glob rules.
- Auto-approval no longer applies to path-qualified executables or executables that resolve inside the project, so a project-local `ls` cannot inherit the system `ls` exemption. Relative `PATH` entries fail closed and unknown executable identity prompts.
- Command execution on Unix now uses `/bin/sh` directly instead of resolving the shell through a potentially project-controlled `PATH`.

## 🔧 Maintenance

- Added regression tests for typed rule migration, backend scope validation, broker permission identity and executable lookup.
- Applied consistent Rust formatting across the backend.

## ⚠️ Notes

- Requires Node 24 or newer to build from source.
