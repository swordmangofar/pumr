# pumr v0.8.0

A release about what a command may do and what you can make the agent do. The
operating system now confines every command the agent runs, hooks run commands of
yours at fixed moments of its work, and the permission prompts can remember an MCP
tool or a folder of sensitive files. The chat box got slash commands, with a side
question that never enters the session and your prompts as commands of their own.
`read` opens pictures, PDFs and notebooks, the Git tab was hardened against losing
work, and pumr can be summoned from the command line, which makes a summon key
possible on Wayland.

## 🚀 Features

- Added a sandbox for commands. The operating system confines every command the agent runs and whatever it starts: `sandbox-exec` on macOS, Landlock on Linux 5.19 and newer. A command writes only to the project, your extra folders, temp folders and the caches of build tools (`~/.cargo`, `~/.npm`, `~/.cache` and the like), and cannot read the folders that hold keys (`~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.kube`, `~/.azure`, `~/.config/gcloud`, `~/.config/gh`, `~/.netrc`). git, ssh, gpg, `gh` and the cloud tools keep the folders they work with, as long as nothing else is chained onto the line. On macOS a second mode, "Files and network", also closes the network except for this machine and for commands whose hosts you allowed.
- Added running outside the sandbox: a command the sandbox stops is told so and can ask to run outside it, which asks you every time and is never remembered. Settings → Sandbox has the mode, the folders commands may also write to, the folders they cannot read, and the commands that always run outside it, for tools that bring a sandbox of their own such as browser tests.
- Added hooks: commands of yours that pumr runs before a tool call, after one, or when the agent wants to finish. The model does not decide whether they run. A hook gets the call as JSON on standard input with the field names Claude Code uses (`tool_name`, `tool_input`, `tool_response`) and the file the call names as `$PUMR_FILE`. Exit code 0 goes on; exit code 2 hands what the hook printed to the agent and, before a tool call, refuses the call. A hook at the end of a turn sends the agent back to work at most once. Hooks filter by tool (`edit|write`) and file (`*.ts`), stop after 60 seconds unless you set another limit (up to 600), apply to all projects or one and live in Settings → Hooks, never in the repository.
- Added slash commands: typing `/` in an empty chat box lists them, narrowed as you type. `/model`, `/mode`, `/effort` and `/provider` list their choices with the current one ticked, `/revert` goes back to your last prompt after a confirmation.
- Added `/btw`, a side question about the session or anything else. It is answered below the chat box by the session's model without tools, also while the agent works, and never becomes part of the session. Its cost counts towards the session.
- Added your prompts as commands: `/code-review src/auth` sends the Code Review prompt along with what follows it, for that one message. Five prompts are built in, to call, edit or reset: UI/UX Designing, Code Review, Documentation Writer, Bugfix and the new Test Writer.
- Added "don't ask again" for MCP tools: a permission prompt can remember one tool of one server, whatever its arguments, for the chat and its subagents or always. A server whose configuration changed asks again, and Settings lists the always-allowed tools to take one back.
- Added releasing a folder's sensitive files: a command that uses a key, token or credential file still asks every time and no command rule changes that, but "don't ask again" can release the sensitive files directly in that folder, for the chat or always. Folders below it are not included, and Settings lists the released folders.
- Added pictures, PDFs and notebooks to `read`. A picture (png, jpg, gif, webp, up to 5 MB) is shown in the chat and seen by a model with vision; a PDF is read as text by page range (`pages`, the first 10 pages by default); a Jupyter notebook comes as its cells with what they printed. Any other binary file is named by its kind instead of read.
- Added a Run button next to Copy on every block of shell commands in the chat. It runs the block in the terminal dock: in the terminal on show while that waits at its prompt, in a new one while a program runs there. The agent now puts a command you have to run yourself, because it needs `sudo` or a password, into a block of its own.
- Added `pumr --toggle`, `--open`, `--minimize` and `--hide`: they hand the window action to the running pumr, and `--toggle` and `--open` start it when it is not running. Bound to a key in the desktop's keyboard settings, this is the summon key for Wayland, where apps cannot register system-wide shortcuts. Settings → Window shows the command for your install, such as the path of the AppImage, ready to copy.
- Added a hotkey that switches between Planning and the mode the session was in before: `Cmd`+`Shift`+`P`, elsewhere `Ctrl`+`Shift`+`P`. It can be remapped.
- Added a choice of logo under Settings → Appearance: Sitting puma (the new default), Classic face, Shaded puma, and Puma, tail up. It is shown in the header and as the app icon while pumr runs (the Dock on macOS, the window and taskbar icon on Windows and Linux X11).
- Added a project picker to the Workspace and Git tabs. They show the project you pick instead of following the open session, also with no session open, and the choice is remembered.
- Added a stash dialog to the Git view, with an optional message and "Include untracked files", and a Branch button that creates a branch at HEAD.
- Added a keep-awake button to the header. It takes effect at once, also for turns that are already running.
- Added skills from opencode plugins: the `skills` folder of a plugin that opencode loads from a local path is searched. A collection may also group its skills in folders of their own, up to three levels deep.
- Added the MCP start to the chat: a turn that waits for a server says which one it is starting, Stop ends the wait, and a message that had to do without a server lists it.
- Added guidance for the default model: with a provider connected but no default model, the chat says so with a link to the settings, and the providers page points at the field.

## ✨ Improvements

- Commands and hooks run with the variables your shell profile exports, also when pumr was opened from the Dock or a launcher, so a script that reads `$MY_CREDENTIALS/token` finds it as it does in your terminal.
- Loading a skill gives the agent its `SKILL.md` and names the files next to it (up to 40), which the agent reads without a prompt when the instructions call for them. Descriptions written as YAML block scalars are read.
- Local MCP servers start in the project folder and get it as their root. A server that exits fails its calls at once with its exit status and last lines of output, instead of after 60 seconds, and is reconnected on the next message. A remote server's lost session is reopened and the call sent once more. Stopping a server also stops what it started (`npx`, `uvx`, `docker run`), and quitting pumr stops MCP servers and background commands.
- MCP configuration: `opencode.jsonc`, comments and trailing commas in JSON, and servers marked as disabled in their config file are no longer offered. On Windows, `npx` and other `.cmd` launchers start.
- `glob`, `ls` and `grep` say when their output was cut, and `grep` names the files it skipped as too large or not text.
- `edit` and `write` keep Windows line endings, and an `edit` that only differs in whitespace keeps the indentation around it.
- Writing a hidden `.env` file asks first, and files in the scratch folder or a folder you opened are no longer hidden by a rule for a folder above them.
- A tool that the session's mode withholds is refused when the model calls it anyway.
- Command checks: command substitutions in heredocs are judged like inline ones, the output files of `curl -o` and `wget -O` are checked as paths, and `$VAR` resolves to your login shell's value.
- Git: staging a conflicted file that still contains conflict markers asks first, however it is staged. Discard no longer deletes a nested repository, worktree or submodule and says what it kept. A failed merge, cherry-pick or stash names the conflicted files, and the commit form no longer carries over to another project.
- Starting pumr a second time brings the running window to the front.
- The composer toolbar stays on one row, with reasoning as a single chip. The `@` file picker lists files the agent created since it was last opened.
- Questions from the agent can be answered with the keyboard alone, and the revert dialog opens with Confirm focused.
- Linux without GPU compositing: the backdrop is painted once, and the spinner and the remaining animations move in steps instead of redrawing the window every frame.
- Marketplace servers without a start command get one from their package type: `npx` for npm, `uvx` for PyPI, `docker` for container images.
- Everything clickable shows the pointer cursor, Settings is a gear icon in the header, and the sidebar tab is called Sessions.

## 🐛 Bug Fixes

- Fixed messages losing their formatting on send: runs of spaces were collapsed, the indentation of pasted code was stripped and blank lines were merged.
- Fixed a prompt being lost when it could not be sent, such as with a model without an API key. It returns to the chat box with its mentions and attachments.
- Fixed mention pills and pasted-text blocks vanishing from a draft after switching sessions.
- Fixed a key pressed in a preview, menu or dialog also answering the permission prompt underneath.
- Fixed opening a binary file showing an empty editor that could be saved over the file.
- Fixed reverting to a checkpoint deleting ignored files when the turn had changed a `.gitignore`.
- Fixed a branch and a tag of the same name being confused: a merge, rebase or new branch could take the tag.
- Fixed pumr's git commands acting on another repository when pumr was started from a git hook or `rebase --exec`.
- Fixed unstaging or discarding part of a change joining two lines at a missing final newline, and line actions reaching a diff other than the one shown.
- Fixed unstaging before the first commit, a corrupted history with `log.showSignature` set, and Fetch, Pull and Push being enabled in a folder that is no repository.
- Fixed marketplace updates never arriving, and marketplace servers from npm and PyPI starting with a wrong command.
- Fixed MCP tools with names longer than 64 characters getting every request refused by the provider, a local server's connection ending on output that is not UTF-8, and a server URL with its key appearing in an error.
- Fixed Anthropic refusing a conversation after a reply that held only whitespace, and one cut-off tool call breaking every later request.
- Fixed a system-wide shortcut that could not be registered looking active. Settings → Window now shows a warning with the reason.
- Fixed Stop letting the remaining calls of a batch run, and Stop in a subagent's tab that had already reported back ending the parent chat's turn.
- Fixed a compaction that finished after the chat was reverted being applied anyway.
- Fixed pictures being sent to a model without vision after a model switch.
- Fixed session counts of projects including subagent sessions, and "Today" and "Yesterday" in the session list being wrong after midnight.
- Fixed streamed text fading in with "reduce motion" on.
- Fixed the global `AGENTS.md` not being found on Windows.

## 🔧 Maintenance

- Added 57 git safety tests on real temporary repositories, covering discard, commit and amend, branch switching, pull, push, reset, cherry-pick, revert, rebase, stash, odd file names and inherited environment variables.
- Added Rust tests for the sandbox, hooks, the read formats, MCP connections and tool grants, secret folders, skill discovery, the window commands and the settings migration.
- New e2e specs cover slash commands, the side question, MCP, MCP tool approvals, secret folders, rendering, hooks and the sandbox; the Git spec grew to staging, discard, commit, stash, branch, merge, rebase and push. The fake backend keeps a small git repository with refs, commits, stashes and conflicts, and answers the native confirm dialogs.
- Debug builds keep their own data folder, seeded once from the installed one.
- The icon scripts generate all four logos, and every platform icon was regenerated.
- Added `pdf-extract` for the text of PDFs, `sha2` for the fingerprint of an MCP server's configuration, `objc2` for the Dock icon on macOS and `gdkwayland-sys` for window activation on Wayland.

## ⚠️ Notes

- The sandbox is on by default, in the "Files" mode, also for existing installs. A command that writes outside the listed folders or starts a browser of its own fails inside it until it asks to run outside, or until you add it under Settings → Sandbox. Linux before 5.19 and Windows have no sandbox pumr can use, so commands run unconfined there; closing the network is only possible on macOS.
- Hooks run as you wrote them, without permission prompts and outside the sandbox.
- Your prompts lost their on/off switch and are no longer appended to every session's system prompt. Call one with `/name`, or name it in a mode. "Bugfixer" is now "Bugfix"; built-in prompts you had not edited get the new text, edited ones are kept.
- Loading a skill no longer includes the other Markdown files of its folder; they are listed for the agent to read.
- `read` of a picture needs a model that is listed with vision. Other models, custom and local servers included, are pointed to `screenshot`.
- Outside macOS the terminal tab hotkeys default to `Ctrl`+`T` and `Ctrl`+`W` (before: with `Shift`); a focused terminal takes them for its own tabs.
- On Wayland the in-app window shortcut does not work reliably. Bind the command from Settings → Window to a key in the desktop's keyboard settings instead.
