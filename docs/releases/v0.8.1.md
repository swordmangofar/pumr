# pumr v0.8.1

A release that makes the agent ask less often without letting it do more. pumr
remembers how you like to work, a project carries the variables of its toolchain,
and a folder can be opened for reading only or trusted on `PATH`, so the prompts
that came back with every new command line are answered once. On macOS a tighter
sandbox takes over inline code instead of asking. The sandbox itself got stricter:
commands no longer reach pumr's own data or start other apps. OpenRouter providers
your account blocks are marked, questions can be moved out of the way, and the
terminal draws the icons of prompt themes.

## 🚀 Features

- Added memory: pumr remembers how you like to work. When a message shows a lasting preference ("ask me for every finding whether to fix it"), the agent proposes it, and once its answer is there a card asks whether to remember it, with the text to edit; "Remember that ..." works too. Nothing is saved without your yes. pumr asks at most once per chat and once a day, less often after each no, and "Don't ask again" stops the suggestions. What is remembered goes to the agent in every chat and project, and Settings → Memory lists it to edit, add to or switch off.
- Added variables for a project: the pencil next to a project in the sidebar now opens its settings, with a field for one `NAME=value` per line, such as `JAVA_HOME` and a `PATH` that starts with its `bin`. `$NAME` and `~` are filled in. Every command and hook of that project starts with them, the rules read command lines with them, and the agent is told that they are set, so a project that needs JDK 11 on a machine that defaults to another one needs no prefix on every command.
- Added folders for reading only: remembering a prompt about reading or listing a folder, or about a command that only reads, opens the folder for reading and nothing else. Changes there still ask, and a folder is opened for changes when a change asks for it. Settings → Workspace lists both kinds.
- Added trusting a folder on `PATH`: a command that changes `PATH` is judged by the folders it adds. One the agent cannot change runs unasked; one it can change asks, because a file there would run in place of a program. The prompt names the folder, and "don't ask again" trusts that folder on `PATH`, for the chat or always, rather than one command line. Settings lists the trusted folders to take one back.
- Added a tighter sandbox for inline code on macOS. While "All commands inside the project" is on, inline node or python code (`node -e`, `python3 -c`), scripts fed to them through a heredoc and commands whose arguments are only known when they run no longer ask: they run in a sandbox that reaches only this machine, writes only to the project, your extra folders and temp folders, starts no apps, reaches no other program and cannot change git hooks or `.git/config`. Code that names a file outside the project, a sensitive file or another host asks as before, and a script the tight sandbox stops can ask for the prompt and run normally. Settings → Sandbox turns this off.
- Added blocked providers to the OpenRouter provider list: providers that your OpenRouter privacy settings, provider lists or guardrails rule out are shown as blocked, with OpenRouter's reason, and cannot be picked. A session pinned to a provider that is now blocked leaves the routing to OpenRouter.
- Added moving a question: dragging the header of a question from the agent moves it anywhere in the window, so the chat behind it can be read. The place is kept for later questions and across restarts, and a button puts it back.
- Added a preview to the background settings. It shows the backdrop behind a few glass panels and follows the sliders, now named "Background visibility" and "Background blur"; the app itself is restyled when a slider is let go.
- Added the icons of prompt themes to the terminal: the glyphs that Powerlevel10k, Starship and similar themes draw with come from a bundled icon font, so they show without installing a Nerd Font.

## ✨ Improvements

- A permission prompt nobody answers stays open until someone does. It used to be denied after ten minutes, which made the agent give up on a command you would have allowed on coming back. After ten minutes the waiting turn no longer keeps the computer awake.
- The sandbox closes pumr's own data folder, which holds the chats of every project, the settings and the snapshots, to commands: a script in one project does not read the chats about another. The folder stays closed whatever folders you allow, except for the skills you installed, whose scripts the agent runs.
- On macOS a sandboxed command starts no other app. `open` works only as a command of its own, where the rules judge it; an `open` inside a script or a build tool starts nothing, and the agent is told so.
- `open` and `xdg-open` are judged by what they are handed: a web link follows the website list like any network command, a page on this machine opens without asking, a file or an app asks.
- A prompt about a path outside the project says whether the agent wants to read or change it, and a prompt whose folder would only be opened for reading says so.
- The prompt for running outside the sandbox names pumr's own data among what the command could then read.
- pumr's `PATH` loses its empty and relative entries, however pumr was started. Those name whichever folder a command runs in, so a file of the project could stand in for a program.
- Where inline code asks every time (Linux, Windows, or with the tight sandbox off), the agent is told to write a script file to the scratch folder and run that instead.
- A question with one answer starts on its first option, so Enter sends it as it is.
- The notice about MCP servers a message had to do without can be dismissed.
- The "trains on data" label of an OpenRouter provider is read from the data policy OpenRouter publishes for that provider.
- An exported debug log holds what was granted for the chat without being saved (folders, `PATH` folders, released folders, command rules), the `PATH` its commands start with, the names of the project's variables and the remembered preferences. The debugger shows the remembered preferences as a step of the system prompt.

## 🐛 Bug Fixes

- Fixed a subagent's tab losing what its tools returned once the subagent had finished.
- Fixed the agent being sent back to run a check right after you refused that command, which raised the same prompt again.

## 🔧 Maintenance

- Added Rust tests for the memory and how often it asks, the tight sandbox, pumr's closed data folders, `open`, folders for reading, `PATH` folders, project variables, the OpenRouter routing probes and the prompt that waits.
- New e2e specs cover the memory and toolchains (folders on `PATH`, project variables, folders for reading); the settings, sandbox, prompts, slash command, MCP and terminal specs grew with the features above. The fake backend handles the new commands.
- New component specs cover the memory card, the memory settings and the project dialog.
- Bundled Symbols Nerd Font (1 MB, with its license) under `public/fonts`.

## ⚠️ Notes

- The tighter sandbox for inline code is on by default on macOS, also for existing installs, and applies only while "All commands inside the project" is on. Inline code that asked before then runs without a prompt, inside that sandbox. On Linux and Windows inline code keeps asking.
- Commands that read pumr's data folder now fail inside the sandbox and have to ask to run outside it. Landlock can only allow, so on Linux a project or an allowed folder that contains pumr's data folder opens it.
- Folders you allowed before stay open for changes. Only folders remembered from now on by a prompt about reading are opened for reading only.
- Memory is on by default and applies to every project. Settings → Memory switches it or its suggestions off; the entries are kept.
- Blocked providers are found by asking OpenRouter's router with requests it turns down before a provider is called, so no model answers them.
